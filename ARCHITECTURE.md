# DoTogether — Architecture Overview

## 1. Layered Architecture (Clean Architecture)

```
┌──────────────────────────────────────────────────────┐
│  DoTogether (WebApi)                                 │
│  Controllers · Middleware · Program.cs · Dockerfile  │
├──────────────────────────────────────────────────────┤
│  DoTogether.Application                              │
│  Services · DTOs · Interfaces                        │
├──────────────────────────────────────────────────────┤
│  DoTogether.Infrastructure                           │
│  EF Core DbContext · TokenService · SeedData         │
├──────────────────────────────────────────────────────┤
│  DoTogether.Domain                                   │
│  Entities · Value Objects · Enums                    │
└──────────────────────────────────────────────────────┘
```

| Layer              | Responsibility                                        | Dependencies                       |
| ------------------ | ----------------------------------------------------- | ---------------------------------- |
| **Domain**         | Entities, value objects, enums. Zero dependencies.    | —                                  |
| **Application**    | Business logic (services), DTOs, interface contracts. | Domain                             |
| **Infrastructure** | EF Core, PostgreSQL, JWT, external concerns.          | Application, Domain                |
| **WebApi**         | ASP.NET Core controllers, middleware, DI wiring.      | Infrastructure (transitive to all) |

## 2. Domain Model

### Core separation

| Entity            | Purpose                                                                        |
| ----------------- | ------------------------------------------------------------------------------ |
| `ChoreTemplate`   | Recurring chore definition (title, recurrence rule, assignee, start/end date). |
| `ChoreOccurrence` | A specific instance generated from a template for a particular due date.       |
| `ChoreEvent`      | Immutable audit/history record. Every state change produces one event.         |

### Recurrence engine

`RecurrenceGenerator` is a pure-static class that generates `DateOnly` sequences from a `RecurrenceRule` value object. It handles:

- **Daily** — every N days with fast-forward for distant ranges.
- **Weekly** — ISO day-of-week selection with interval-week skipping.
- **Monthly** — day-of-month clamping: if the target day exceeds the month's length, it clamps to the last day (e.g., day 31 → Feb 28/29).

### Timezone policy

**One timezone per household** (`Household.TimeZoneId`, IANA identifier).

Rationale: partners in a 2-person household share a physical home. A single timezone eliminates ambiguity about when a chore is "due" or "missed" and keeps calendar aggregation straightforward. All due dates are `DateOnly` values in the household's local timezone. The "missed" transition fires when the household-local date advances past the due date.

### DST handling

Because due dates are `DateOnly` (not instants), DST transitions never create ambiguous or skipped occurrences. The only instant-level conversion is "is it past end-of-day in the household timezone?" which is evaluated via `TimeZoneInfo.ConvertTimeFromUtc`.

## 3. Authentication & Device Tokens

- **Username/password flow**: client registers with username, display name, and password, then logs in with username and password to receive a JWT access token plus refresh token.
- **Refresh token rotation**: on refresh, the old token is revoked and replaced.
- **Device push tokens**: `DevicePushToken` entity stores FCM/APNs tokens per user, ready for push notification integration.

## 4. Idempotency & Offline Retry Strategy

Every mutation endpoint (`complete`, `undo`, `skip`, `reassign`) requires a `clientOperationId` (UUID) generated by the client.

- **Server-side dedupe**: before applying a mutation, the server checks `IdempotentOperation` for a matching `clientOperationId`. If found, the original serialized response is returned without side effects.
- **ChoreEvent** records also store the `clientOperationId` with a unique index, providing an additional safety net.
- **Optimistic concurrency**: `ChoreOccurrence.Version` is an EF Core concurrency token. If two devices submit conflicting mutations, the second will receive a `DbUpdateConcurrencyException`.
- **Ordering**: events are ordered by `OccurredAtUtc`. The server clock is authoritative. Client-perceived order is preserved through the idempotency key — retries for the same operation always return the same result.

## 5. Data Integrity

- **Transactions**: EF Core wraps each `SaveChangesAsync` in a transaction. Mutations that create both a `ChoreEvent` and an `IdempotentOperation` are atomic.
- **Soft delete**: `BaseEntity.IsDeleted` with EF Core global query filters. No data is physically removed.
- **Key indexes**: composite indexes on `(HouseholdId, DueDate, Status)` for calendar queries, `(ChoreTemplateId, DueDate)` for dedup during generation, unique indexes on `ClientOperationId`.

## 6. Error Model

All errors are returned as **RFC 9457 Problem Details** via `ExceptionHandlingMiddleware`:

| Exception                     | HTTP Status |
| ----------------------------- | ----------- |
| `UnauthorizedAccessException` | 403         |
| `InvalidOperationException`   | 409         |
| `ArgumentException`           | 400         |
| `KeyNotFoundException`        | 404         |
| Other                         | 500         |

## 7. Local Development

```bash
docker compose up -d        # PostgreSQL + API
# Or run just PostgreSQL and use dotnet run:
docker compose up -d postgres
dotnet run --project DoTogether
```

Seed data creates two users (Alice & Bob), a household, and three chore templates (daily, weekly, monthly with day-31 clamping) with pre-generated occurrences.
